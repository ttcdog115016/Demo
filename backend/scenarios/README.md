# 實務應用情境測試說明

本資料夾為三種實務應用情境（醫療研究、金融分析、交通流分析）之測試腳本與設定檔。
每個情境以一份測試資料集，依序執行資料前處理、K-匿名化、差分隱私、再識別攻擊模擬與 CAP 前後對比，
另有一組權限控管與資料存取檢查。

測試資料集為模擬資料，不含任何真實個人資料，隨完整交付套件之 `03_測試腳本/實務應用情境/data/` 提供，
使用時複製至本資料夾之 `data/`。執行結果寫入 `out/`，不隨版控保存。

## 前置準備

環境建置方式與 `docs/manual_test/README.md` 相同（`uv sync` 或 `pip install -r requirements.txt`）。
以 uv 執行者，下列 `python ...` 指令前加 `uv run`。

K-匿名化之假名化鹽值由 `.env` 之 `OPEN_PETS_DEFAULT_SALT` 提供；未設定時不加鹽，照常執行。

## 一、測試資料集

`scenarios/data/` 置三份 CSV：`醫療研究.csv`（14 欄）、`金融分析.csv`（15 欄）、
`交通流分析.csv`（14 欄），每份 500 萬筆，涵蓋數值、字串、類別與時間四種資料型態。

## 二、設定檔

`scenarios/configs/` 置 18 份設定檔，即每個情境六份，對應六個處理端點各自須開啟之區塊：

| 檔名 | 用途 |
|---|---|
| `<情境>_preprocess.json` | 資料前處理 |
| `<情境>_k.json` | K-匿名化 |
| `<情境>_dp.json` | 差分隱私 |
| `<情境>_risk_k.json` | 再識別三攻擊（以 K-匿名產生去識別資料） |
| `<情境>_risk_dp.json` | 再識別三攻擊（以差分隱私產生去識別資料） |
| `<情境>_cap.json` | CAP 前後對比 |

各情境之處理對象：

| 階段 | 處理對象 |
|---|---|
| 資料前處理 | 姓名、車牌與證號雜湊、居住里與起點路口截至區或縣市、時間截至日、數值夾限、空值填補、代碼正規化 |
| K-匿名化 | 準識別欄位（出生日期／出發時間、性別、居住里／起點路口、車種）泛化後檢驗 k、l。居住里與起點路口已於前處理截至區或縣市，K-匿名化不再泛化 |
| 差分隱私 | 每個情境三個數值欄、一個時間欄與一個類別欄逐欄配置預算 |
| 再識別風險 | 以同一組準識別欄位與一個敏感欄位執行三攻擊，並對 K-匿名化與差分隱私前後資料各執行 CAP |

三個情境的時間類預算配給就診日期、交易時間、抵達時間。

## 三、執行情境測試

```bash
python scenarios/run_scenarios.py                     # 三情境各七步
python scenarios/run_scenarios.py --scenario 金融分析  # 只跑一種
python scenarios/run_scenarios.py --skip-risk         # 只跑前三步
```

處理後之資料集寫入 `scenarios/out/`，各步驟之耗時與輸出彙整為 `scenarios/out/執行結果.json`。

## 四、執行權限控管與資料存取檢查

```bash
python scenarios/check_access_control.py
```

檢查建立兩種角色之使用者、帳密正確登入、密碼錯誤與帳號不存在之拒絕、重複建立帳號之拒絕、
一般使用者呼叫帳號管理端點應被拒絕（403）、密碼未以明文留存，以及稽核軌跡之鏈式完整性，
結果寫入 `scenarios/out/權限控管檢查結果.json`。

本檢查會於 `data/users.db` 建立 `scenario_admin`、`scenario_user` 兩個測試帳號，
檢查完畢後應予刪除（`DELETE /api/v1/users/{username}`，或直接刪除 `users.db`）。

登入相關端點需簽章金鑰才啟用，本腳本會自行為受測伺服器帶入一組僅供檢查使用的金鑰，
故不必先於 `.env` 設定 `OPEN_PETS_JWT_SECRET`；若已設定則沿用該值。

## 執行時間參考

500 萬筆之執行時間見實務應用情境測試報告；權限控管檢查約 20 秒。
