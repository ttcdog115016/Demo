## 八、Step4 報告的預設 δ 與取消運算（2026-10-31）

### δ 可以是 0

- **後端本來就支援，預設值也是 0**：
  - 數值與日期欄位 δ=0 時改用離散 Laplace（`Geometric`），為純 ε-DP；
  - 類別欄位一律 δ=0（k-RR）；
  - 未設定全域 δ 時不送 `default_delta`，後端以 0 處理。
- **報告原本誤印 0.00001**：前端在未設定全域 δ 時以 1e-5 補值（`complianceReport.ts`）。現已改為 0，並顯示「0（未設定，純 ε-DP）」；「本次消耗 δ」為 0 時同樣加註「0（純 ε-DP）」。
- **輸入框允許 0**：全域 δ 與欄位 δ 的下限由 1e-10 改為 0，驗證改為「≥ 0 且 < 1」。全域 δ 明確填 0 時也會送出 `default_delta: 0`，讓設定檔與畫面一致。
- **舊紀錄不受影響**：既有處理紀錄保存的是當時的快照，舊報告仍會顯示當時寫入的值。

### 取消運算時後端同步停止

- **原本**：按「取消運算」只中斷前端連線。後端會把整個運算跑完再丟掉結果，期間佔住唯一的運算名額，下一次運算必須排在後面。
- **現在**有兩條路徑，任一條成功即可：
  1. 前端以 `X-Client-Run-Id` 標頭標記這一輪運算，按取消時呼叫 `POST /api/v1/runs/{id}/cancel`。這條路徑經 cloudflared 也一定送得到。
  2. 後端偵測到用戶端中斷連線。
- **停止時機**：引擎在迴圈斷點停下，包括三攻擊的每一輪與每個攻擊、指認性的每次迭代、K-匿名每個欄位、DP 每個欄位、前處理每個步驟。停下後回 499 `ERR_CANCELLED` 並立即釋放運算名額，維運日誌記為「使用者已取消運算」（不算失敗）。
- **提醒調整**：取消請求送達後端時，不再顯示「後端可能仍在計算」的 5 分鐘提醒；只有取消請求送不到後端，或通道逾時（524）時才提醒。
- **限制**：單一 pandas 或 scikit-learn 呼叫（例如推斷性攻擊的 RandomForest 訓練）無法中途打斷，最久要等目前這一步做完。

**實測**（2 萬筆三攻擊；n_iter 20000、3 輪；開始 3 秒後取消；之後立刻送出一個前處理請求）：
