### 2-4【低】後端 CORS 設成 `allow_origins=["*"]`＋`allow_credentials=True`，一般 API 沒有驗證 Host
- **位置**：BE `app/api/server.py:51-59`
- **工具**：Semgrep（`python.fastapi.security.wildcard-cors`）
- **問題**：任何網站都能從使用者瀏覽器呼叫 `http://127.0.0.1:8765/api/v1/*` 並讀取回應。Starlette 在 `*` 加 credentials 時會回傳請求的 Origin。目前的緩解措施：處理端點都要求 Bearer token（存在 WebView 內，外站拿不到）、登入有鎖定機制（`auth.py:29`，900 秒）、首次建立管理員已在 `launcher.py:341-347` 檢查 Host 與 Origin。剩下的風險是：外站可以讀取未登入就能存取的端點（`/api/v1/status`、setup 狀態），也可以故意輸錯密碼把本機管理員鎖住 15 分鐘（DoS）；一般 API 也沒有防 DNS rebinding 的 Host 檢查。
- **影響**：**exe**（本機服務可被同機瀏覽的任意網頁存取）；線上 demo 是同源部署，不需要 `*`。
- **修法**：把 `allow_origins` 改成環境變數白名單（exe 是同源，可以直接留空、不掛 CORS；線上 demo 只填實際網域），並把 `allow_credentials` 改成 False（前端用 Authorization 標頭，不用 cookie）。exe 再加上 `TrustedHostMiddleware(allowed_hosts=["127.0.0.1","localhost"])`，順帶擋掉 DNS rebinding。

### 2-5【低】前端 production 相依有低成本修補（axios、yaml）
- **位置**：`package.json:20`（axios ^1.18.1，實際 1.18.1）、`package.json:35`（yaml 2.8.1）
- **工具**：osv-scanner
- **問題**：
  - axios 有 12 個弱點，大多只影響 Node 的 http/http2 adapter，瀏覽器用不到。但有兩類在瀏覽器也成立：「繼承來的 headers/FormData 造成標頭注入」與「prototype pollution gadget」。後者需要另一個 prototype pollution 漏洞配合才能利用。
  - yaml 會被過深的巢狀結構打爆 stack，而 `src/utils/configFileParse.ts:15` 會解析使用者上傳的設定檔。後果只是當前頁籤當掉。
- **影響**：exe 與線上 demo 都有（打包進前端），實際風險低。
- **修法**：`npm i axios@^1.20.0 yaml@^2.8.3`，重新 build 前端並跑測試。
